# FrameFlow 交互设计文档 v2.0

> 设计方向：风格 A「克制专业」  
> 核心模型：常驻但不打扰的小型桌面控制中心；用户明确点击“开始录屏”后，才进入屏幕绘制与录制状态。

## 1. 从用户视角重新定义产品

用户不会把 FrameFlow 理解为一个“编码工具”，而会把它理解为一个随时可打开的录屏助手。

用户期待它像微信等常驻应用一样：

- 平时可以最小化到 Windows 系统托盘或 macOS 菜单栏，不占据任务栏和桌面空间。
- 点击图标后出现一个完整但紧凑的窗口，而不是直接进入全屏框选。
- 在窗口里先确认保存路径、音频来源、最近录制和输出方式。
- 只有点击明确的“开始录屏”入口后，才进入区域绘制状态。
- 录制结束后回到同一个窗口，看到刚才的视频以及高清、轻量两个版本。
- 关闭主窗口不等于退出应用，后台处理和快捷录制继续可用。

### 1.1 用户始终需要回答的五个问题

1. 我现在录制的是哪个范围？
2. 麦克风和系统声音是否正常？
3. 文件会保存到哪里？
4. 录完后我会得到哪些文件？
5. 我关闭或最小化窗口后，录制任务是否仍在继续？

所有界面状态都必须让这些问题有明确答案。

## 2. 产品窗口模型

FrameFlow 由四层界面组成，用户在不同任务中只看到必要的一层。

| 层级 | 用户看到的内容 | 出现时机 |
| --- | --- | --- |
| 系统托盘 / 菜单栏 | 图标、开始录屏、录制状态、最近内容、退出 | 应用常驻后台时 |
| 紧凑主窗口 | 录制入口、保存路径、输入状态、最近录制、设置 | 用户主动打开应用时 |
| 屏幕覆盖层 | 屏幕遮罩、绘制区域、比例与录制菜单 | 用户点击“开始录屏”后 |
| 录制状态条 | 状态、时长、音频、暂停、完成 | 正在倒计时或录制时 |

### 2.1 打开、最小化、关闭与退出

| 用户动作 | Windows | macOS | 结果 |
| --- | --- | --- | --- |
| 点击应用图标 | 打开或聚焦主窗口 | 打开或聚焦主窗口 | 显示完整紧凑界面 |
| 点击最小化 | 最小化到任务栏 | 最小化到 Dock | 录制与处理继续 |
| 点击关闭 | 默认隐藏到系统托盘 | 默认隐藏窗口，菜单栏保留 | 不退出进程；首次显示解释 |
| 点击托盘/菜单栏图标 | 打开快速菜单 | 打开快速菜单 | 可开始、暂停、完成、打开主窗口 |
| 选择“退出 FrameFlow” | 退出应用 | 退出应用 | 若有任务，先说明影响并确认 |

首次关闭窗口时提示：

> FrameFlow 会继续在后台运行，方便随时录屏。你可以从系统托盘重新打开。  
> 操作：知道了 / 关闭时直接退出

该提示只出现一次，行为可以在“设置 → 通用”中修改。

## 3. 紧凑主窗口

### 3.1 设计目标

主窗口需要“完整”，但不需要“大”。它应只占屏幕的一小部分，让用户仍然看得到桌面、浏览器、文档或正在准备录制的内容。

- 建议默认尺寸：`720 × 520 px`。
- 建议最小尺寸：`640 × 460 px`。
- 记住用户最后一次尺寸和位置。
- 首次打开位于当前屏幕中央；后续在上次所在显示器恢复。
- 主窗口不是仪表盘，不使用大面积数据卡和无意义统计。

### 3.2 信息优先级

主窗口从上到下回答四件事：

1. 从哪里开始录制。
2. 文件保存到哪里。
3. 录制输入是否准备好。
4. 之前录制的内容在哪里。

### 3.3 主窗口结构

```text
┌────────────────────────────────────────────────────────────┐
│ FrameFlow                           设置   最小化   关闭    │
├────────────────────────────────────────────────────────────┤
│  录下重点，同时获得两个版本                                │
│  [ ● 开始录屏 ▾ ]     区域录制 · 快捷键 Alt+Shift+R       │
│                                                            │
│  保存到                                                    │
│  D:\FrameFlow\Recordings          [更改] [打开文件夹]     │
│                                                            │
│  录制输入                                                  │
│  麦克风：MacBook Microphone ● 正常                         │
│  系统声音：开启           摄像头：关闭                     │
│                                                            │
│  最近录制                                      查看全部 →  │
│  [缩略图] 产品演示  02:18  轻量已完成 · 高清已完成   ⋯     │
│  [缩略图] Bug 反馈  00:42  轻量已完成 · 高清处理中   ⋯     │
└────────────────────────────────────────────────────────────┘
```

### 3.4 明显的录制路径入口

主按钮必须是窗口中唯一的高强调按钮：

- 文案：`开始录屏`
- 图标：实心录制圆点
- 默认行为：进入“区域录制”绘制状态
- 下拉选项：区域录制、窗口录制、全屏录制、上次区域
- 按钮下方显示当前默认方式和快捷键
- 不使用“新建”“捕获”等需要理解的抽象词

按钮位于窗口内容区左上方的第一视觉位置，而不是隐藏在标题栏、侧边导航或托盘菜单中。

### 3.5 保存路径入口

保存路径必须在录制前可见，因为这是用户最关心但常被录屏软件隐藏的信息。

- 直接显示完整路径，空间不足时保留磁盘和末级目录，中间省略。
- 路径整行可点击，点击打开文件夹。
- 提供独立的“更改”按钮，打开系统目录选择器。
- 路径变更后显示轻提示：`后续录制将保存到此位置`。
- 路径不可写、磁盘断开或空间不足时，在主按钮上方显示阻塞性错误。
- 结果文件默认放入以录制日期命名的文件夹，可在设置中关闭。

### 3.6 最近录制

最近录制让用户确认过去的内容没有丢失，也提供继续处理的入口。

- 主窗口显示最近 3–5 个录制组。
- 一个录制组只出现一次，内部包含“轻量预览”和“高清母版”两个版本。
- 每行显示缩略图、名称、时长、时间、双版本状态和更多菜单。
- 点击行进入结果详情；双击默认播放轻量预览。
- 支持拖出轻量文件、打开高清文件、重命名、显示文件位置、删除。
- 后台处理中显示精细进度，但不阻止用户开始下一次录制。

## 4. 用户主流程

### 4.1 标准路径

1. 用户从桌面、任务栏或托盘打开 FrameFlow。
2. 主窗口出现，用户看到保存路径、输入状态和最近录制。
3. 用户点击明显的“开始录屏”。
4. 主窗口隐藏，系统进入屏幕绘制状态。
5. 用户拖拽绘制录制区域。
6. 绘制完成后，选区上方出现比例、尺寸、音频和“开始录制”菜单。
7. 用户确认后开始倒计时。
8. 录制中只保留紧凑状态条。
9. 用户点击“完成”，覆盖层消失，主窗口重新出现并进入处理状态。
10. 轻量版优先就绪，用户可以立即预览或复制；高清版继续在后台生成。

### 4.2 快速路径

熟练用户可以通过全局快捷键直接进入绘制状态，不必先打开主窗口：

- Windows：`Alt + Shift + R`
- macOS：`⌥ + ⌘ + R`

即使使用快速路径，停止录制后仍回到完整结果窗口，而不是只弹出通知。

### 4.3 托盘路径

托盘/菜单栏菜单保持简洁：

- 开始区域录制
- 开始窗口录制
- 上次区域
- 打开 FrameFlow
- 最近录制（最多 3 条）
- 设置
- 退出 FrameFlow

录制进行中时，菜单顶部替换为当前时长、暂停/继续和完成。

## 5. 全状态交互定义

### S0：后台常驻 / 已最小化

**用户看到：** 主窗口不可见，系统托盘或菜单栏保留 FrameFlow 图标。  
**用户理解：** 应用仍可随时使用，后台任务不会中断。  
**关键动作：** 单击图标打开快速菜单；双击 Windows 托盘图标打开主窗口。  
**状态提示：** 无任务时使用普通图标；录制中增加红点；处理中增加环形进度。

### S1：主窗口默认态

**用户看到：** 开始录屏、保存路径、输入状态和最近录制。  
**用户理解：** 一切已准备好，并且知道文件会保存在哪里。  
**主动作：** 开始录屏。  
**次动作：** 更改路径、调整输入、打开最近内容、进入设置。

### S2：主窗口异常态

异常就近出现，不集中到一个“诊断中心”：

- 权限缺失：出现在对应输入项和开始按钮上方。
- 麦克风无输入：输入项显示黄点，但允许静音录制。
- 路径不可用：开始按钮暂时禁用，提供“选择新位置”。
- 空间不足：显示需要空间、当前空间和清理入口。
- 编码器不可用：自动回退到兼容方案，并允许查看详情。

### S3：绘制状态

**进入：** 点击开始录屏或全局快捷键。  
**界面：** 当前屏幕轻度变暗，光标变为十字，顶部显示简短说明。  
**用户动作：** 拖拽绘制、点击窗口选择、Esc 取消。  
**反馈：** 实时显示宽高；按住 Shift 锁定最近比例。  
**注意：** 此时不显示完整主窗口，避免遮挡用户要选择的内容。

### S4：选区就绪状态

**进入：** 用户完成拖拽。  
**界面：** 选区保持原亮度，外部遮罩；上方出现悬浮菜单。  
**菜单：** 模式、比例、尺寸、麦克风、系统声音、开始录制、更多。  
**用户动作：** 改比例、移动/缩放选区、切换输入、重新绘制或开始。  
**默认焦点：** 开始录制。

比例切换以选区中心为锚；受屏幕边界限制时给出一次性提示，不静默改变尺寸。

### S5：倒计时状态

**界面：** 选区中心显示 3、2、1；悬浮菜单收为“正在开始 · 取消”。  
**用户动作：** Esc 取消并回到选区就绪。  
**音效：** 默认关闭，可在设置中开启。  
**目标：** 给用户移动鼠标和准备说话的时间，不制造强烈闪屏。

### S6：录制状态

**界面：** 选区边缘出现克制红色描边；悬浮条显示 `REC`、时长、麦克风、暂停和完成。  
**自动收起：** 鼠标离开 2 秒后收为“红点 + 时间 + 完成”。  
**用户动作：** 静音、暂停、继续、添加标记、完成或取消。  
**完成：** 立即停止并保存，不二次确认。  
**取消：** 需要确认，并说明临时文件是否保留。

### S7：暂停状态

**界面：** 状态条由红色变为琥珀色，文字变为“已暂停”。  
**状态播报：** 明确提示“录制已暂停”；不只依靠颜色。  
**用户动作：** 继续、完成、取消。  
**屏幕内容：** 保持可见，不覆盖大面积暂停蒙层。

### S8：停止与处理状态

**进入：** 用户点击完成。  
**界面：** 覆盖层消失，紧凑主窗口恢复，并自动打开本次录制详情。  
**处理顺序：** 先封装轻量预览，再完成高清母版。  
**用户理解：** 已成功保存录制，不需要停留等待。  
**可执行动作：** 再次录制、最小化、打开保存位置；轻量完成后立即播放和复制。

处理窗口关闭或最小化后，任务继续在后台运行，托盘图标显示处理状态。

### S9：轻量版完成、高清处理中

这是最重要的中间状态：

- 播放器立即加载轻量版。
- “轻量预览”卡片显示完成，主按钮为“复制轻量版”。
- “高清母版”卡片显示进度和预计剩余时间。
- 用户可以关闭窗口、开始下一次录制或继续等待。
- 高清失败不会影响轻量版。

### S10：全部完成

**界面：** 播放器、轻量预览卡片、高清母版卡片全部可用。  
**主动作：** 复制轻量版。  
**次动作：** 打开高清版、打开文件夹、重新导出。  
**信息：** 显示格式、尺寸、帧率、体积、时长和路径。  
**最近录制：** 本次录制作为一个录制组回到列表顶部。

### S11：处理失败 / 可恢复

- 只失败一个版本时，另一个版本保持可用。
- 失败卡片显示可理解原因、重试和“改用兼容格式”。
- 应用异常退出后，下次启动在主窗口顶部显示恢复条。
- 恢复条文案：`发现一段未完成的录制，可尝试恢复。`
- 用户可以恢复、查看临时文件或丢弃。

## 6. 主窗口内的设置结构

不设置独立设置页。主窗口顶部是随录制生命周期变化的状态区；保存位置、录音输入、输出和最近录制在其下方按行展开。一次只展开一个分组，避免主窗口变成长表单。

| 分组 | 用户要解决的问题 | 主要设置 |
| --- | --- | --- |
| 通用 | 应用如何启动、最小化和关闭 | 开机启动、关闭到托盘、语言、通知 |
| 录制 | 屏幕和声音如何被录制 | 麦克风、系统音频、光标、点击效果、倒计时 |
| 主视频 | 主文件需要多清晰、是否包含声音 | 格式、最大分辨率、帧率、包含音频 |
| 预览 | 是否生成小文件，以及预览形式 | 生成开关、MP4、WebM、动态 WebP、动态 AVIF、最大分辨率、帧率、包含音频 |
| 封面 | 是否自动为每个视频版本生成对应封面 | 自动生成封面开关 |
| 保存位置 | 文件存在哪里、如何命名 | 默认目录、日期目录、命名模板、自动清理 |
| 快捷键 | 如何快速开始与控制 | 开始、暂停、完成、静音、自定义冲突检查 |
| 隐私与更新 | 数据是否上传、应用如何更新 | 遥测、日志、自动更新、权限诊断 |

### 6.1 主窗口的渐进披露

- 展开区域只呈现用户需要做出的决定，不解释编码、选帧或文件组织机制。
- 文案优先描述结果，例如“生成封面”，不暴露内部实现语言。
- 没有可选项的系统行为不做成信息卡、说明列表或不可编辑表单。
- 普通用户只选择格式、清晰度和是否生成预览/封面。
- 格式与编码器组合由系统约束，不允许选择无效组合。
- CRF、码率、关键帧等参数不进入主窗口首版。
- 折叠行实时显示结果摘要，例如：`MP4 · 最大 1080p · 30 fps · 有声音`。

### 6.2 “生成轻量预览版”开关

预览版本不是所有用户都需要，因此在主窗口“输出”展开区提供一级开关：

`生成轻量预览版`，默认开启。

开启时：

- 每次录制结束后生成轻量预览和高清母版两个版本。
- 显示格式、最大分辨率、帧率和“包含音频”。
- 格式可选 MP4、WebM、动态 WebP、动态 AVIF。
- 选择动态 WebP 或动态 AVIF 时，“包含音频”自动关闭并隐藏，因为动态图片不承载音频。
- 结果页默认优先加载轻量版本。
- 轻量版本先完成后可以立即复制或拖出分享。

关闭时：

- 后续录制只生成高清母版。
- 预览格式、尺寸、帧率和音频等从属设置收起。
- 输出折叠行显示：`仅主视频`。
- 结果页不显示空的“轻量预览”卡片，也不提示轻量版本缺失。
- 历史录制不受影响，过去已经生成的轻量文件继续可用。
- 用户仍可从高清母版的更多菜单中选择“一次性生成轻量版”。

切换开关不会删除现有文件，也不会影响正在录制或正在处理的任务，只对下一次录制生效。界面需明确显示：`从下次录制开始生效`。

### 6.3 两个视频的“包含音频”开关

- 主视频和预览视频分别拥有独立的“包含音频”开关，默认均开启。
- 关闭主视频音频不会影响预览视频；关闭预览视频音频也不会影响主视频。
- 预览选择动态 WebP 或动态 AVIF 时，预览音频固定关闭，界面不展示不可用开关。
- 历史录制不受修改影响；录制中不可修改，改动从下一次录制生效。

### 6.4 “自动生成封面”开关

设置界面只显示一个开关和一句结果说明：

- 开关：`生成封面`
- 说明：`高清和预览视频各一张 JPG`

不显示选帧方式、图片格式、尺寸、保存位置或实现原理。

内部固定规则不在界面展示：封面跟随对应视频尺寸，与对应视频保存在一起。关闭预览视频时，只生成高清封面。关闭封面开关时，不保存独立封面文件。

自动封面独立于轻量版本：关闭轻量预览不应自动关闭封面。两者组合共有四种有效状态：

| 轻量预览 | 自动封面 | 本次录制输出 |
| --- | --- | --- |
| 开启 | 开启 | 高清母版 + 高清封面 + 轻量预览 + 轻量封面 |
| 开启 | 关闭 | 高清母版 + 轻量预览 |
| 关闭 | 开启 | 高清母版 + 高清封面 |
| 关闭 | 关闭 | 仅高清母版 |

### 6.5 主窗口输出摘要

主窗口“输出”折叠行显示一行简短摘要，随选择实时变化：

- `每次录制：高清、预览、封面`
- `每次录制：高清、封面`
- `每次录制：仅高清`

用户无需从多个表单项推断最终会得到哪些文件。

## 8. 用户视角的异常原则

错误信息按以下顺序表达：

1. 发生了什么。
2. 对当前录制有什么影响。
3. 用户现在可以做什么。

例如不要只显示 `Encoder initialization failed`，而应显示：

> 无法生成 WebM 轻量版。高清母版不受影响。你可以重试，或改用兼容性更好的 MP4。

## 9. 无障碍与键盘路径

- 不使用鼠标也能打开应用、开始录制、调整区域、暂停、完成并复制轻量版。
- 录制、暂停、处理和失败状态同时使用文字、图标和颜色。
- 状态变化通过辅助技术播报，但不持续播报计时。
- 选区可用方向键移动，`Shift + 方向键` 每次移动 10px。
- UI 缩放到 200% 时，主按钮、路径入口和完成按钮不可被折叠。
- 减少动态效果模式下移除缩放动画，只保留短暂透明度变化。

## 10. 原型状态覆盖

交互原型需要至少覆盖以下状态，并允许直接切换验证：

1. 主窗口默认态
2. 绘制区域态
3. 选区就绪态
4. 倒计时态
5. 正在录制态
6. 已暂停态
7. 轻量完成、高清处理中
8. 全部完成态
9. 最小化到托盘态
10. 路径或权限异常态
11. 设置：轻量与封面均开启
12. 设置：轻量关闭、封面开启

## 11. 设计验收标准

- 打开应用后，用户 3 秒内能找到“开始录屏”。
- 用户在录制前无需进入设置就能确认保存路径与麦克风状态。
- 主窗口不会大面积遮挡桌面，用户仍能看到准备录制的内容。
- 进入绘制状态有明确因果，应用不会在启动时突然全屏遮罩。
- 绘制、就绪、倒计时、录制、暂停和处理状态仅看界面即可区分。
- 主窗口关闭或最小化不会意外中断录制和转码。
- 双版本被理解为同一次录制的两个用途，不会在历史列表中重复出现。
- 轻量版完成后即可使用，无需等待高清版本。
- 路径、权限、空间与编码失败均提供可执行的解决入口。
- 用户在设置页无需理解编码器，也能明确知道下次录制会生成哪些文件。
- 关闭轻量预览后，从属设置即时收起，结果页不出现无意义的空卡片。
- 自动封面与轻量预览互相独立，四种开关组合均有明确输出结果。
