# 智能框选需求与首版实现

## 目标

进入区域录制后，FrameFlow 应立即根据鼠标位置给出可选择区域，让用户无需从空白遮罩开始精确拖动。常见窗口可以单击采用；需要任意区域时仍可直接拖动自由框选。

## 用户交互

1. 进入框选后，目标屏幕显示暗色遮罩与顶部操作提示。
2. 鼠标悬停在可识别窗口上时，窗口边界自动高亮，候选区域内部保持明亮。
3. 在候选区域上单击，直接采用当前智能选区。
4. 按下鼠标后移动达到 5 个物理像素，立即切换为自由框选，不再吸附窗口。
5. 浏览器命中可识别的网页渲染视口时，优先高亮网页视口，不包含标签栏、地址栏和工具栏。
6. 智能识别失败时保持完整遮罩，用户仍可拖动完成自由框选。
7. `Esc` 取消；框选完成后沿用既有边框缩放、顶部手柄移动和开始录制流程。

## 识别规则

- 只扫描当前录制屏幕内、鼠标位置下方的可见顶层窗口，并按 Windows Z 序选择最上层候选。
- 排除 FrameFlow 自身窗口、桌面、任务栏、透明窗口、工具窗口、最小化窗口及 DWM cloaked 窗口。
- 使用 DWM 扩展窗口边界，避免把不可见阴影误计入选区；不支持 DWM 时回退 Win32 窗口边界。
- Chromium/Edge 及其他暴露 `Chrome_RenderWidgetHostHWND` 的浏览器优先选择鼠标所在网页渲染视口；旧式 `Internet Explorer_Server` 视口同样支持。
- 浏览器未暴露可靠视口句柄时回退整个浏览器窗口，不使用固定高度猜测工具栏。
- 跨越多显示器的候选窗口裁剪到当前录制屏幕，录制范围始终保持单屏物理像素坐标。
- 透明输入层继续保持接近不可见；四块外围遮罩不会覆盖候选区域，避免 Chromium 因顶层窗口遮挡而暂停视频渲染。遮罩与四条预览边框通过同一个 `BeginDeferWindowPos` 批次更新，失败时保留上一帧，不执行逐窗口几何回退。该批次只保证 Win32 几何更新的一致性，不保证多个分层窗口在同一个 DWM 合成帧完成重绘。

## 首版非目标

- 不识别网页 DOM 元素、图片或文字块等语义区域。
- 不通过 OCR 猜测内容边界。
- 不承诺识别所有 Firefox 或自绘 UI 浏览器的网页视口；未可靠命中时选择整个窗口。
- 不改变录制后的边框编辑、倒计时、编码或输出流程。

## 验收标准

- 悬停普通应用窗口时，高亮区域随鼠标切换到最上层可见窗口。
- 悬停 Chromium 浏览器网页内容时，高亮区域排除浏览器工具栏；悬停无法识别的浏览器区域时安全回退窗口边界。
- 单击智能候选可进入现有“选区已就绪”状态。
- 拖动超过阈值生成自由选区，拖动方向不影响矩形结果。
- FrameFlow 提示条、遮罩和边框不会成为候选窗口。
- 负坐标副屏、跨屏窗口和不同 DPI 屏幕继续使用物理像素并保持选区在当前屏幕内。
- 智能识别不可用时自由框选、取消和重新框选仍可使用。
- 连续移动鼠标或自由拖框时，半透明遮罩和边框不出现逐块移动造成的缝隙、重叠或闪烁，浏览器视频保持渲染。

## 已否决的闪烁修复尝试

- `SWP_NOCOPYBITS`：已删除。它会在遮罩改变尺寸时丢弃旧客户区像素，新区域等待背景刷补齐，可能加重选区下沿和屏幕底边闪烁。
- `RedrawWindow(... RDW_UPDATENOW)` 加 `DwmFlush`：已删除。同步重绘和等待 DWM 只会阻塞当前选择线程，不能把多个 layered HWND 的内容提交合并成一个合成事务，实机验证仍然闪烁。
- 单个全屏 layered HWND：不采用。即使中间像素透明，其完整窗口矩形仍可能触发 Chromium 遮挡判断，使网页视频暂停渲染或捕获到静止画面。
- 统一 `BeginDeferWindowPos`：保留，但只作为几何一致性和失败时保留上一帧的改进，不再将其视为闪烁修复。

## 当前已知问题

四块外围 layered HWND 在选区连续变化时仍可能独立完成表面 resize 与 DWM 合成，实机可见闪烁主要集中在选区下沿及屏幕最下方。后续方案必须同时满足“不以全屏 HWND 覆盖浏览器视口”和“动态遮罩不依赖多个窗口表面同步 resize”两个约束。
