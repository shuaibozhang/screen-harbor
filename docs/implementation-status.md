# FrameFlow 实施状态

## 当前里程碑

阶段 C：本地录制库与桌面生命周期。

## 当前架构

- React/TypeScript/Tauri 2 提供主窗口、选区工具条和录制工具条。
- `frameflow-core` 维护唯一可信录制状态机；前端状态由后端事件驱动，不保留跨录制轮次的“保存中”本地状态。
- SQLite 仅作为可恢复的录制元数据索引，输出目录中的正式 MP4 始终是事实来源；应用启动时自动扫描并对账。
- `frameflow-recorder` 是不依赖 Tauri 的录制引擎边界，统一拥有 WGC、WASAPI、混音、暂停/恢复、实时静音、统计和 MP4 收尾。主程序以同一个 `frameflow.exe --capture-worker` 启动独立录制进程，通过带协议版本和请求 ID 的 JSON Lines 管道调用；Tauri 层只负责窗口、状态机和事件转发。
- 进程启动时启用 Per-Monitor V2 DPI。原生选区、WGC 裁剪和基础画布统一使用物理像素；DPI 只影响界面布局与坐标换算，不决定成片分辨率。输出层采用 OBS 式独立策略，默认保留原始物理分辨率，也可选择最高 1080p、720p 或自定义边界，由 D3D11 视频处理器等比缩小且绝不放大。
- 原生选区专用线程会再次显式固定为 Per-Monitor V2，避免 WebView/Tauri 调用线程的临时 DPI 上下文将鼠标和边框坐标虚拟化为逻辑像素。
- 框选阶段使用近乎不可见的 Win32 原生输入层接收鼠标，并用四个独立原生窗口实时绘制选区预览。完成框选后销毁输入层，只保留可编辑窄边框和移动手柄；支持整体移动及八方向缩放，录制开始后锁定为点击穿透。
- 选区确认和录制阶段仅显示 520 × 56 的不透明 WebView 工具条；不存在全屏透明 WebView，也不冻结后方画面。
- WGC 捕获生产者在独立 MTA 线程取得显示器纹理，通过 `CopySubresourceRegion` 裁剪后发布到容量为 1 的最新帧槽，不执行 CPU readback，也不调用编码器。裁剪目标来自 4 槽 D3D11 纹理池，只有未被媒体线程引用的纹理才会复用；池满直接丢弃本次捕获，不逐帧分配显存，也不让编码背压阻塞桌面捕获。
- 独立 `frameflow-media` MTA 线程唯一拥有帧率调度、D3D11 Video Processor、Media Foundation Sink Writer 和 MP4 收尾。24/30/60 FPS 输出时钟从最新帧槽采样；静态画面复用最新帧，编码落后时跳过已错过的输出槽位，媒体时间轴继续按真实录制时钟前进。
- Media Foundation 使用 D3D11 Video Processor 将 BGRA 转为 NV12，并请求 Sink Writer 优先采用硬件 H.264 编码器。初始化后通过 `IMFSinkWriterEx` 查询实际选中的编码 MFT，并与硬件编码器注册信息核对；视频时间戳由输出时钟槽位生成，正常负载保持所选帧率，过载时保留真实时长并表现为丢帧。
- 录制先写入 `.mp4.part`。停止命令立即进入 Finalizing，Worker 停止音频与 WGC、完成 MP4 `Finalize`，成功后原子改名为 `.mp4`。主进程管道意外断开时，Worker 也会主动执行相同收尾流程。
- 收尾协调器超过 20 秒会解除界面锁定并保留 `.part`，避免录制工具条永久停在“保存中”。

## 已完成

- Windows 显示器枚举、WGC 支持探测、Per-Monitor V2 DPI 和 `WDA_EXCLUDEFROMCAPTURE`。
- 原生实时选区层、反向拖拽、最小选区、Esc 取消、重新框选、整体移动、八方向缩放和四边框窗口生命周期。
- 物理像素选区模型；已删除逻辑像素选区命令和旧 WebView 选区编辑器。
- 连续区域捕获、显示器尺寸变化时重建帧池、暂停/恢复和带确认的停止控制。
- 可配置的恒定 24/30/60 FPS 输出时钟和精确 MP4 时间线；设置持久化到应用配置目录。
- 读取主窗口所在显示器的 Windows 标称刷新率，设置界面按刷新率推荐 24/30/60 FPS；高于刷新率时提示重复帧风险，但保留用户显式选择。59 Hz 按 60 Hz 档处理，VRR 瞬时变化不用于动态改写恒定输出时间线。
- GPU BGRA 裁剪、NV12 转换、H.264 MP4 编码和原子文件收尾。
- 后端驱动的录制工具条状态，第二次录制不会继承上一轮 Finalizing 状态。
- Windows NSIS 安装包配置。
- WASAPI 默认麦克风和系统输出端点发现；主窗口展示真实设备名称与可用状态，设备不存在或查询失败时保持静音录制能力。
- 事件驱动的 WASAPI Shared Mode Loopback 会话；使用默认输出设备的原生混音格式，在专用 MTA 线程排空音频包，正确处理静音缓冲区、QPC/设备位置、启动握手和幂等停止。当前尚未接入 MP4。
- 48 kHz 双声道 f32 标准化音频总线；解析 PCM/IEEE Float/WAVE_FORMAT_EXTENSIBLE，支持 16/24/32-bit PCM、单声道复制、多声道按通道掩码下混，以及跨 WASAPI 包保持状态的采样率转换。
- 通用 WASAPI 输入引擎同时支持默认系统输出 Loopback 和默认麦克风 Capture；两者共用事件驱动线程、格式解析、包读取和停止协议，并将隐私权限拒绝与设备失效分类为可降级错误。麦克风探针仅供用户主动运行，本轮未自动读取麦克风内容。
- 双路音频混音器使用 QPC 100 ns 时间戳将系统声与麦克风放入统一的 48 kHz 主时间线；支持独立启用、静音和增益，自动补静音间隙、裁剪重叠、按块限制时钟修正幅度，并以带峰值限幅的 1024 帧 AAC 输入块输出。
- MP4 Sink Writer 已支持可选 AAC-LC 立体声音轨：混音 f32 按块转换为编码器兼容的 PCM16，使用 48 kHz 帧号独立计算 100 ns 时间戳与时长，并由 Windows Media Foundation 编码为 128 kbps AAC，与 H.264 共用同一个 Sink Writer。
- WGC 录制会话提供容量为 64 块的非阻塞音频投递队列；WASAPI 回调不会被视频转换或磁盘写入阻塞，瞬时满载只丢弃当前块并保留后续带时间戳输入，不再永久停掉音频源。录制期间每个视频周期最多交错写入 4 个音频块，避免持续生产的音频饿死视频；停止时再完整排空并执行 MP4 Finalize。
- 系统声与麦克风 WASAPI 回调只校正 QPC 时间戳并投递到容量为 128 包的输入队列；独立 `frameflow-audio-mixer` 线程唯一执行格式标准化、重采样、双路混音和 AAC 块生成。实时回调不再获取混音器锁或调用编码队列。
- Media Foundation Sink Writer 的默认输入节流已关闭；FrameFlow 自己的输出时钟负责实时调度，`WriteSample` 不再因内部限速长期阻塞唯一编码线程。
- 应用录制协调器已串联 WASAPI、标准化、混音、AAC 队列和 MP4 收尾：系统声默认开启、麦克风默认关闭，输入设置持久化；混音时间线锚定录制启动时的 Windows QPC，保留设备启动延迟，暂停期间丢弃输入并扣除累计暂停时长；停止时先停止音频生产者、刷新重采样与混音尾块，再停止 WGC 并 Finalize。设备或队列失败只将对应音频源降级，不终止视频录制。
- 主窗口的麦克风和系统声音开关已接通真实后端状态；设备不可用时禁用，录制非空闲状态禁止修改，不再显示不可点击的“接入中”占位控件。
- 录制工具条可分别实时静音/恢复系统声和麦克风；操作仅更新混音控制，不重启 WASAPI 或 AAC。设备启动失败、运行中断开和编码队列降级通过独立音频状态与黄色非阻塞提示呈现，停止和视频保存始终保持可用。
- 录制工具条实时展示已编码帧数、真实编码 FPS、跳过的视频时间槽和丢弃的音频输入包；性能判断不再依赖成片后的人工观察。
- 录制统计协议会报告实际 H.264 编码器名称及硬件加速判定；工具条显示“硬件 H.264 / 软件 H.264 / H.264（未知）”，悬浮可查看 Media Foundation 返回的编码器名称。编码器查询失败只影响诊断信息，不阻断录制。
- 成片验收器可自动读取最近两段或指定 MP4，检查 H.264 视频轨、预期输出分辨率、恒定帧率、时长和 AAC 48 kHz 双声道音轨，并以非零退出码报告不符合项。
- 最近录制已从进程内列表迁移到 SQLite：应用重启可恢复历史，目录内新增或移动的 MP4 会自动补录，缺失和伪 MP4 会从索引清理，损坏的数据库会先归档再从成片重建。主页默认展示最近三条，可展开全部并在资源管理器中定位文件。
- SQLite 录制索引使用 `OnceLock<Result<...>>` 惰性一次初始化；Tauri `setup` 与 WebView 首次 hydrate 并发时共享同一初始化结果，不再暴露短暂的“索引未初始化”状态。首页加载失败会显示错误与重新加载入口，不再永久停留在空白加载壳。
- 录制控制条通过后端状态快照完成初始化，并采用单飞异步轮询读取 Worker 统计；窗口显示前丢失状态事件或 Worker 请求变慢时，不再停在 0 秒或堆积并发请求阻塞停止操作。
- Capture Worker 使用每次录制随机生成、拒绝远程客户端的两条 Windows 单向命名管道传输控制协议：命令与响应各自使用独立内核对象，避免同步全双工读写互相阻塞。stdout/stderr 仅用于日志，媒体组件产生的非 UTF-8 输出无法再污染 JSON。
- 控制条在首次 Worker IPC 失败后停止统计轮询并保留首个错误，避免后续请求用二次“管道关闭”覆盖真正根因。
- Worker 响应读取线程由 panic 边界和持久失败状态监督；异步事件回调单独隔离，回调异常不再直接关闭 stdout 并触发双向管道连锁失败。
- 跨进程统计协议使用 `u64` 毫秒表示已录制时长，并有 JSON 往返测试；采集端从 `Duration::as_millis()` 饱和转换，避免 `u128` 无法被 `serde_json` 反序列化。
- 系统托盘提供显示主窗口和退出入口；主窗口关闭只隐藏到托盘。选区或倒计时阶段退出会先安全取消，录制、暂停、收尾和处理中拒绝退出并将控制条带回前台，避免进程退出造成成片截断。
- 录制引擎已从 Tauri 主协调器完整抽离到独立 crate，并落地带协议版本和请求 ID 的 Start/Pause/Resume/Mute/Stats/Stop IPC。统计协议 v2 包含实际视频编码器信息；音频警告作为 request ID 0 的非请求事件复用同一条输出管道。
- 主程序已支持 `--capture-worker` 模式。父进程串行化控制请求并校验响应版本与 request ID；专用 IPC 读取线程持续排空 stdout 并实时转发异步事件，普通控制请求最多等待 5 秒、Stop 最多等待 18 秒，超时会关闭 stdin 触发 Worker 自动收尾，不会占住 Tauri 录制锁。Worker 独占 `CaptureEngine`，正常 Stop 后返回成片路径和时长，stdin EOF 时自动停止录制并完成 MP4 收尾。Worker 失败会作为录制失败回到现有状态机，不在 UI 层保留另一套生命周期。
- 输出设置区将基础画布和编码尺寸解耦：原始模式不经过缩放，缩放模式保持选区宽高比并生成偶数尺寸；旧版只包含 `max_resolution` 的配置会迁移为原始模式，不再因 Windows DPI 自动降低画质。

独立录制 Worker 已完成，进入实机验收：连续完成两轮带系统声音录制，并分别覆盖暂停/恢复、实时静音和正常停止；随后对第二轮成片执行自动验收。

录制开始时锁定本轮音频设备；设备中途断开后仅将对应输入降级为静音并提示，视频继续录制，下次录制重新读取默认设备。当前产品不引入录制中的设备热切换和音频电平显示。

## 本地体验与打包

- 开发运行：`npm run desktop:dev`
- 裸程序构建：`npm run desktop:build`
- Windows 安装包：`npm run package:windows`
- 录制输出：`%USERPROFILE%\Videos\FrameFlow`
- 最近两段成片验收：`npm run validate:recordings -- -- --expected-size 1920x1080 --expected-fps 30 --audio required`
- 指定成片和工具条时长验收：`npm run validate:recordings -- -- "D:\path\capture.mp4" --expected-duration 10 --audio required`

成片验收器使用行业通用的 `ffprobe` 读取容器与轨道元数据；系统需安装 FFmpeg，或通过 `--ffprobe D:\path\ffprobe.exe` 指定可执行文件。任一文件缺少视频轨、不是 H.264、物理尺寸或帧率不符、时长超差，或者所需 AAC 48 kHz 双声道音轨缺失时，命令会返回非零退出码。
