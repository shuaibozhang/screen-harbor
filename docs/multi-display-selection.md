# 多显示器自动框选需求与架构

## 产品边界

ScreenHarbor 继续只提供区域录制。用户不需要在首页预先选择录制方式或显示器：点击“开始录屏”或使用全局快捷键后，可以直接在任意已连接显示器上操作。

本功能支持多显示器环境，但不支持跨屏选区或同时录制多块显示器。一次录制始终绑定一块显示器，并使用该显示器的物理像素坐标和 DPI。

## 交互流程

1. 进入框选时，每块显示器分别出现本地原生遮罩。
2. 鼠标在哪块显示器单击智能候选或开始拖动，该显示器就成为本轮录制屏幕。
3. 首块产生有效操作的显示器获胜，其他显示器的遮罩立即关闭。
4. 智能窗口选择、自由框选、边框调整、倒计时和录制继续沿用现有单屏流程。
5. 选区被限制在获胜显示器内；跨屏窗口候选裁剪到该显示器边界。
6. `Esc` 取消整轮框选。
7. 框选期间显示器拓扑、分辨率或 DPI 发生变化时，安全取消本轮框选并返回首页。

## 架构决策

- `frameflow-windows` 的 `NativeDisplaySelectionSession` 是多显示器原生会话协调边界。它为每块显示器拥有一个既有的 `NativeSelectionSession`，并保证首个显示器声明后只保留该会话。
- Tauri 应用层不再持久化“录制显示器”。它只在收到首个原生选区事件后创建 `ActiveSelection { display, region }`。
- `ActiveSelection` 之后仍是唯一的单屏录制事实来源；WGC、裁剪、编码和输出配置无需感知多显示器协调过程。
- 首页设置中的刷新率提示使用主窗口所在显示器作为参考信息，不代表预先选择了录制屏幕。
- 每块原生选区线程继续使用 Per-Monitor V2 DPI 和物理像素，避免把不同缩放比例的屏幕合并为一个逻辑坐标表面。

## 非目标

- 选区跨越两块或更多显示器。
- 同时录制多个显示器。
- 在录制过程中把选区迁移到另一块显示器。
- 将不同 DPI、刷新率或分辨率的显示器合成为一个输出画布。

## 验收标准

- 单显示器行为与原有区域框选一致。
- 主窗口位于屏幕 A 时，可以在屏幕 B 完成智能选择或自由框选。
- 屏幕 B 获胜后，屏幕 A 的遮罩关闭，最终 `RegionSelection.display_id` 为屏幕 B。
- 左侧负坐标副屏和不同 DPI 的副屏使用正确的物理像素坐标，选框与成片范围一致。
- 任意时刻只能有一个显示器成为本轮录制源，后到事件不能改写已选显示器。
- 框选阶段发生显示器变化时，不保留失效选区，也不进入录制。
