# ScreenHarbor Beta 发布检查表

## 自动检查

- [x] 所有清单版本号一致。
- [x] 前端测试和录制验收器通过。
- [x] Rust 全工作区测试通过。
- [x] NSIS 安装包成功生成。
- [x] 发布清单和 SHA-256 校验文件成功生成。
- [x] 安装包明确记录为未签名 Beta。

执行 `npm run release:beta` 可以重新运行测试、构建并生成 `release/<版本>/` 发布目录。

## 发布前人工检查

- [ ] 在没有 Node.js、Rust 和 FFmpeg 开发环境的 64 位 Windows 10 22H2 上安装。
- [ ] 在受支持的 Windows 11 版本上安装。
- [ ] 确认安装程序显示的产品名称为 ScreenHarbor。
- [ ] 确认能够正常卸载且不会删除用户录制文件。
- [ ] 验证 SmartScreen 提示后的安装路径，并将实际步骤写入下载页。
- [ ] 验证单屏、多屏以及不同 DPI 缩放下的区域选择。
- [ ] 分别验证无音频、仅系统声音、仅麦克风和双音频录制。
- [ ] 验证暂停、继续、停止保存和异常退出恢复。
- [ ] 验证中文和英文切换。
- [ ] 验证磁盘空间不足提示。
- [ ] 随机抽查母版、预览及封面可正常播放或打开。
- [ ] 对发布目录中的安装包重新计算 SHA-256，并与 `.sha256` 文件比较。
- [ ] 使用 Windows Defender 扫描安装包。

## 发布页面检查

- [ ] 标题包含 `ScreenHarbor 0.2.0-beta.1` 和 `Beta`。
- [ ] 上传安装包及对应 `.sha256` 文件。
- [ ] 复制 `CHANGELOG.md` 中当前版本说明。
- [ ] 提供隐私政策和软件许可链接。
- [ ] 明确说明安装包尚未签名，Windows 可能显示“未知发布者”。
- [ ] 明确说明当前没有自动更新，用户需要手动下载安装新版本。
- [ ] 提供唯一且可持续维护的反馈渠道。

## 发布后

- [ ] 使用发布页面实际下载一次安装包，并验证哈希。
- [ ] 保存发布页、安装包和哈希文件的长期备份。
- [ ] 收集 Windows 版本、显示配置、音频配置和复现步骤，不要求用户公开私密录屏。
- [ ] 严重数据丢失、无法停止录制或错误删除文件时，立即撤回该版本并发布说明。
